# Apple video playback and offline downloads

Movies use a completed server VOD playlist when one is available. TV and documentary preparation is not supported by the current server; those categories retain direct downloads for AVPlayer-compatible formats. The server preparation response supplies the fingerprinted playlist URL; the client does not assume a cache key or file path. A direct compatible movie can use the existing playback response while it is not prepared. An MKV, WebM, or transcoded movie waits for complete VOD preparation with an explicit loading message; the client does not give AVPlayer a knowingly unsupported raw container. Saved movie packages resolve locally before any server request and use saved local progress.

Download for Offline requests server preparation, displays preparation status, then hands the complete VOD playlist to `AVAssetDownloadURLSession`. Apple owns the resulting HLS package; Sonder stores its path relative to the app container with the title, source item, completion date, and measured storage size. It never moves package contents. An offline copy becomes available only after the task completes and its asset cache reports that it is playable offline.

The OS-owned session continues transfers during app suspension and reconnects after a background launch. Pending server-preparation intentions are persisted and resumed when the app next opens; preparation polling itself does not run indefinitely in the background. Pause and Resume operate on the existing asset task. Cancel removes the transfer and its intent; Remove Download deletes the saved package. The server may finish its reusable conversion after a device download is canceled.

Same-origin asset URLs receive the configured access token as a query parameter and documented HTTP cookie options. The server carries query authentication from the playlist into its child playlist and segment URLs. Tokens are not included in the persisted item metadata or playback event log. Audio, PDF, and EPUB retain their existing file download path.

This native implementation must be built and installed as an updated iOS app. It is separate from browser offline storage, and deploying the server does not update an installed iPhone app. A simulator compile establishes build compatibility; real-device background, interruption, and offline playback still require device acceptance.
