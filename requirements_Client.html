Client Requirements

Sonder client integration requirements for Plex-like library sync, Libby-like browsing, and book-native support.

This document is the shared contract between the server and client teams. The client should stay light, discover the server easily on LAN, connect cleanly over Tailscale or a manual URL, and render a polished media library experience for video, ebooks, and audiobooks. The client should consume server-authored Plex import context and Sonder's native audiobook index instead of rediscovering or scraping metadata itself.

Goals

  • Make connecting to a Sonder server as easy as opening a Plex or Libby-style app and seeing a library immediately.
  • Support local LAN discovery and explicit Tailscale-based remote access without requiring the client to scan networks aggressively.
  • Keep the client fast, battery-friendly, and cache-first.
  • Show books, audiobooks, movies, and TV in a way that feels native to each category.
  • Use server-authored metadata and artwork as the source of truth.
  • Trust `.sonder/sonder-context.json` and the server's local audiobook cache for migrated libraries.

Connection Modes

Local Loopback access for the host Mac. Always supported. No pairing required for localhost.
LAN Auto-discover via Bonjour/mDNS when the server allows LAN sharing. Client should use the discovery payload and server TXT records. Default posture is open access unless the server later enables restrictions.
Tailscale Explicit server URL using MagicDNS or the tailnet IP. The client should not assume automatic discovery; it should consume a provided URL and only use a token if the server requires one.
Manual User-entered URL for cases where discovery is unavailable or the server is remote/private.

API Contract

Required endpoints

  • GET /api/health returns server health, port, and availability state.
  • GET /api/library returns the full catalog, progress records, server settings, and theme snapshot.
  • GET /api/discovery returns connection modes, capabilities, endpoints, and theme details for fast onboarding.
  • POST /api/progress/{id} updates resume state.
  • GET /stream/{id} streams playable media when supported.

Discovery payload expectations

  • Must include whether LAN sharing is enabled.
  • Should include a local URL and, when available, a LAN URL or a clear Tailscale hint.
  • Should include capabilities for books, audiobooks, progress sync, media streaming, and theme sync.
  • Should include theme token values so client surfaces can match the host.
  • Should indicate when a library is backed by Plex-imported context or native Sonder audiobook records.

Functional Requirements

  • Cache the last successful server response and show shelves immediately while refreshing in the background.
  • Display connection state clearly: local, LAN discovered, Tailscale connected, offline, unauthorized, or stale.
  • Surface ebook and audiobook shelves separately from video shelves.
  • Use server cover art and summaries when available, with graceful fallback to local artwork or placeholders.
  • Support resume progress for all playable media types.
  • Preserve browsing when the server is temporarily offline.
  • Apply the shared earthy theme tokens consistently across navigation, surfaces, badges, and cards, using sage as the base and Cherry Blossom only as an accent.
  • Render migrated Plex libraries immediately from server-cached context without reindexing on device.
  • Browse audiobooks entirely through Sonder's native server APIs and cached index data.

Definition Of Success

  • Open the client, discover or enter the server, and load the library without manual cleanup.
  • Start a video, ebook, or audiobook, force close the client, reopen it, and resume at the same position.
  • Have the server remember the latest progress so another device can continue from the same point.
  • Keep progress, shelves, and artwork stable when media lives on a remote server or tailnet host.
  • Let the client cache locally so it can relaunch quickly even if the server is temporarily unavailable.

Minimum UI Surfaces

  • Server picker / onboarding screen
  • Home shelves with cached continue-watching
  • Search and filter across the catalog
  • Book shelf and audiobook shelf
  • Title detail with artwork, metadata, and resume
  • Server status and connection health view
  • Settings for manual URL, token, and sync preference
  • Server-authored Plex context display for migrated libraries
  • Native audiobook browsing backed by Sonder's own server index

Non-Goals For v1

  • No automatic internet-wide discovery.
  • No client-side metadata scraping.
  • No background network crawling on random subnets.
  • No public server directory.
  • No forcing the user to manage two separate libraries for the same server.
  • No requiring the client to understand Plex bundle structure or an external audiobook server.

Use this as the shared integration contract for the client team. The server should expose enough discovery and metadata for the client to feel easy to connect, easy to browse, and consistent with the rest of Sonder.
