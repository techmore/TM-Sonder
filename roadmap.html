TM Sonder roadmap

Build the server around discovery, sync, and low-friction access.

The goal is a private-first media system that behaves more like a smart library index than a checkout kiosk. The server should do most of the discovery work, keep the client light, and expose a clean path for both local and Tailscale-backed remote use.

North Star
Server-led discovery
Push curated lists, cached context, and relevant library state to devices instead of making clients crawl everything.
Constraint
Low resource use
Favor cached catalogs, incremental updates, and sparse polling over constant rescans.
Access
Private or public
Support local-only, Tailscale, and optionally public endpoints with explicit authentication.

What is still missing

This fills in the gaps around the current local server: better discovery, better remote behavior, and a roadmap for turning Sonder into a real client/server system instead of just a single machine media host.

Roadmap

Phase 1: stabilize the server surface

Now
  • Add explicit server health, library, and catalog endpoints that can be cached by clients.
  • Introduce clear source states for local, remote available, remote unavailable, syncing, and failed.
  • Make progress updates cheap and incremental so clients can sync resume state without pulling the whole library.
  • Keep the current Mac/web experience snappy even when no remote devices are connected.
  • Document the design system and make sage (`#B0C4B1`) the shared visual baseline across macOS and iOS.
  • Keep `library.json` as the app index and move imported show context into per-root `.sonder/sonder-context.json` caches.

Phase 2: discovery and curation

Next
  • Have the server precompute “best next” lists, recently added lists, continue watching, and focused collections.
  • Support server-side search, faceting, and recommendation hints so clients can stay lightweight.
  • Add book-native views for ebooks and audiobooks with separate shelves, stats, and collection logic.
  • Add selective push or refresh notifications so devices only fetch the data that changed.
  • Build saved views that feel more like library shelves than raw database filters.
  • Carry the shared earthy theme tokens into client shells so both platforms feel like the same product family, with sage as the base and Cherry Blossom only as an accent.
  • Finish the Plex import path so launch-time migration, manual refresh, and stale-aware caching all use the same importer.

Phase 3: remote sync and background efficiency

Next
  • Allow manual download, selective cache, and watch-progress sync before any full media mirroring.
  • Use backoff, version checks, and delta fetches instead of aggressive polling.
  • Favor small metadata payloads and avoid waking the network or disk when a cached response is sufficient.
  • Build a server-side metadata pipeline that can enrich titles with artwork, chapter data, and clean tags without requiring the client to do lookup work.
  • Treat Wikipedia-derived artwork and factual metadata as a reasonable source for creative-commons-friendly enrichment when library files are sparse.
  • Let the server act as the source of truth for title metadata, artwork, and list membership.
  • Make the new book and audiobook enrichment flow the canonical place to resolve cover art, summaries, and publisher-like fields.
  • Expand the importer to handle stale checks, per-show status, and exact root-folder cache refreshes.

Phase 3b: native audiobook server

Next
  • Build Sonder’s own audiobook indexer so it owns ingestion, normalization, and serving end to end.
  • Mirror the useful Audnexus ideas natively: chapter extraction, cached metadata, search, and fast identifier lookup.
  • Store audiobook records, authors, series, narrators, chapters, and cover art in Sonder’s local database.
  • Expose audiobook-specific routes for catalog, detail, chapters, search, and cover art.
  • Support local sidecars and embedded metadata before any optional external enrichment.
  • Keep refreshes fingerprint-based so repeated boots do not rescan unchanged audiobooks.

Phase 4: access models and federation

Later
  • Support explicit pairing and trust tokens only when the operator turns on restrictions.
  • Offer a local-only mode, a Tailscale-private mode, and an optional public mode with strong auth for later.
  • Make remote servers discoverable through configured entries, not silent LAN scanning.
  • Let a device keep browsing a cached library even when the remote source is offline.

Design principles

  • Discovery should feel curated, not noisy. The server should do the heavy lifting.
  • Clients should remain fast on weak devices and low-bandwidth connections.
  • Offline browsing should be graceful, with clear availability states.
  • Authentication and sharing should be explicit and legible to users.
  • Public exposure should be a deliberate choice, not the default path.

Success Criteria

  • Open the iOS client, choose a local or remote server, and reach shelves without manual cleanup.
  • Start a video, ebook, or audiobook on the client, force close the app, reopen it, and resume at the same continuity point.
  • Persist progress on the server so another device can resume from the latest known position.
  • Keep local client cache as a fast fallback, but treat server progress as the source of truth when both sides are available.
  • Support LAN and Tailscale access paths so remote media feels like a normal library, not a special case.
  • Keep artwork, metadata, and theme snapshots in sync so the client can relaunch into a coherent experience.
  • Import Plex context once, cache it locally, and use the cache as the default discovery layer on future boots.
  • Ship a native audiobook server that Sonder owns fully, rather than depending on external audiobook infrastructure.

Suggested API focus

Catalog Versioned library payloads, delta refreshes, and cache-friendly responses.
Discovery Curated shelves, top picks, continue-watching, cached show context, and server-generated list bundles.
Sync Progress, list membership, and optional offline pins before full file sync.
Books Native audiobook ingestion, chapter data, cover art, and identifier-based lookup.
Access Clear LAN and Tailscale URLs, optional auth headers, and an easy path for later restrictions.

Good “missing feature” candidates

  • Remote-server status in the UI.
  • Saved server lists and trust onboarding.
  • Collection curation and pinned shelves.
  • Library-wide search that runs on the server.
  • Bandwidth-aware artwork and metadata loading.
  • Background sync that wakes only when needed.
  • Book-specific artwork, chapters, and series metadata.
  • Separate audiobook and ebook stats, tags, and recommendations.
  • Native Plex context import with a durable `.sonder` cache.
  • Native audiobook server features inspired by Audnexus, but owned entirely by Sonder.
  • Theme presets with documented palette tokens and migration guidance.

Success looks like

A user opens Sonder, sees a curated library immediately, and can move between local and trusted remote servers without thinking about networking details. The server has already done most of the discovery work, and the client stays small, fast, and battery-friendly.
