iOS client roadmap

A lightweight client that feels like a great library app, not a mini desktop server.

The iOS app should be fast to open, cheap to sync, and mostly a viewer/runner for server-authored discovery. Think Libby-style simplicity for browsing and reading, but adapted to media libraries, with the server doing the expensive indexing and the phone staying battery-friendly. It should also trust the server's cached Plex-imported context and native audiobook index instead of rediscovering everything itself.

Client philosophy

  • Keep local state small and cache-first.
  • Prefer server-generated shelves and curated lists over client-side discovery logic.
  • Load artwork, metadata, and progress lazily so the app feels immediate.
  • Make remote access obvious, not hidden behind networking jargon.
  • Optimize for one-handed use and quick continuation of what was already in progress.
  • Make the book experience feel native, with proper ebook and audiobook surfaces.
  • Treat Plex-imported show context and Sonder-authored audiobook metadata as server-owned cache, not client work.

Low resource goals

  • Small sync payloads.
  • Incremental refreshes.
  • Minimal background churn.
  • Respect system power and network conditions.

Server does the heavy lifting

  • Search and ranking.
  • Recommended lists.
  • Availability state.
  • Federated server awareness.

Roadmap

Phase 1: fast first launch

Now
  • Login or connect to an existing server using a URL, with tokens only when the operator enables them.
  • Show cached shelves immediately, even before the network returns.
  • Render continue-watching and local favorites without waiting for a full sync.
  • Keep the initial home screen simple and stable.
  • Adopt the shared earthy palette so the iPhone and iPad shell visually matches the macOS host, with sage as the base and Cherry Blossom reserved for accent moments.

Phase 2: remote browsing

Next
  • Browse server-authored collections, recommendations, and library sections.
  • Support search that runs on the server with compact result payloads.
  • Show availability clearly when remote content is offline.
  • Remember which servers are trusted and what sync policy they use.
  • Show separate ebook and audiobook collections so the UI matches how people actually use the library.
  • Keep the theme tokens and component language in sync with the macOS roadmap so both clients feel coherent.
  • Render cached server context for migrated Plex libraries without forcing a fresh discovery pass on device.

Phase 3: syncing without bloat

Later
  • Sync watch progress, selected shelves, and pinned titles first.
  • Offer manual download for offline use, with clear storage control.
  • Fetch artwork and metadata progressively based on screen size and visibility.
  • Use background refresh sparingly and only when the device is likely to benefit.
  • Surface chapter, cover, and series metadata when it improves the reading/listening experience.
  • Consume server-resolved book and audiobook art instead of redoing Wikipedia lookups on-device.
  • Trust `.sonder/sonder-context.json` and the server's audiobook index for migrated libraries instead of rescraping local media on the phone.

Phase 4: multi-server and access modes

Later
  • Handle local, Tailscale-private, and public-trusted servers in the same UI, with restrictions added only when the server asks for them.
  • Let users add servers explicitly and label them by trust zone, but keep the default flow open and simple.
  • Support switching between servers without losing local cache data.
  • Prepare for federation so one client can see multiple libraries cleanly.
  • Continue to work when the server has imported Plex context or native audiobook records and the client only needs to render.

Success Criteria

  • Open the app, reconnect to the server, and show cached shelves immediately.
  • Start a video, ebook, or audiobook, force close the app, reopen it, and land back at the correct resume position.
  • Sync progress back to the server so another client can continue from the latest saved state.
  • Handle local, LAN, and Tailscale URLs without making the user think about networking.
  • Keep the app responsive while loading artwork and metadata in the background.
  • Respect server-provided restrictions only when they are explicitly enabled.
  • Open a migrated Plex-backed library and show cached shelves immediately from server-authored context.
  • Browse native Sonder audiobook records without any external audiobook server dependency.

Missing client features

  • Server picker and trust onboarding.
  • Cached home shelves and offline browse mode.
  • Server-driven search and discovery.
  • Remote status badges and retry behavior.
  • Download queue and storage manager.
  • Progress sync and resume across devices.
  • Tailscale-aware connection hints.
  • Accessibility-first, low-friction navigation.
  • Dedicated ebook reader and audiobook detail surfaces.
  • Book-native artwork, chapter, and collection treatment.
  • Theme preset support that mirrors the macOS color tokens and documentation.
  • Server-authored Plex import context should render immediately on first open.
  • Native audiobook browsing should be powered by Sonder's own audiobook index and API.

What not to do first

  • Do not build a heavyweight local indexing engine on iPhone.
  • Do not rely on constant polling or background scanning.
  • Do not surface raw server complexity before the library UI is polished.
  • Do not make public sharing the default assumption.
  • Do not force the client to solve metadata enrichment that belongs on the server.

The iOS client should mostly be a fast, reliable window into the server’s curated view of the library, with optional offline support and very deliberate network behavior.
