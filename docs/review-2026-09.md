# TM Sonder — Architecture Review & Improvement Roadmap

*September 2026 · scope: the whole repo, with the Go server (`server/`) as the
authoritative implementation*

---

## Scope & method

Three independent deep-dive audits were run in parallel over the Go backend
(`httpapi`, `library`/`probe`/`transcode`, and the Swift clients + repo/ops),
each producing evidence with function/line anchors. Findings were then
triage-fixed, with every change verified by `gofmt`, `go vet`, and
`go test -race ./...`.

Baseline at review start: **12/12 packages passing**, `go vet` clean, ~6.8k LOC
of non-test Go across 11 packages, plus ~16.6k LOC of Swift across the macOS
app, iOS client, and `SonderAPI` package.

## Executive summary

The Go server is in good shape: clean package boundaries, an acyclic dependency
graph, a well-documented wire contract (`API.md`) with golden tests, and broad
test coverage on the scan/probe/transcode core. It is a credible foundation for
a Plex replacement.

The dominant risks are **not** in the core packages. They are:

1. **A dual-server split.** The Swift macOS app still ships an embedded HTTP
   server (~1.6k LOC + a 444-line embedded web UI) that the Go server fully
   supersedes. Roughly **60% of the macOS target reimplements concepts Go now
   owns**, with measurable wire drift already present. This is the single
   largest maintainability liability.
2. **Data-integrity failure modes around removable storage.** A rescan while a
   NAS share is unavailable could prune the catalog. (Fixed in this pass; see
   below.)
3. **A browser-reachable localhost trust boundary.** Loopback peers bypassed
   auth entirely with no `Host`/`Origin` validation, so a DNS-rebinding page
   could read the pairing token and enumerate the filesystem. (Fixed.)
4. **A proven data race on the shared config** between settings writes and
   request reads. (Fixed.)
5. **Catalog-cache thrash from playback progress pings**, which invalidate the
   entire 16 MB `/api/library` payload and its ETag on every heartbeat.
   (Not yet fixed — top of the remaining roadmap.)

This pass landed **14 fixes across 21 files** with new regression tests; the
rest is captured as a prioritized roadmap below.

## What changed in this pass (all verified)

### Data integrity

| Change | Where | Why |
| --- | --- | --- |
| Failed/empty library scans no longer prune their items | `scanner.ScanAll`, `Store.RetainOnly` | An unmounted NAS share or empty autofs stub used to delete every cataloged item for that library on the next scan. Items in a failed library are now preserved, and an activity event is logged. |
| New `safeScan` setting (default **on**) | `config.Config`, `library.Scanner` | Treats "library resolves but yields zero files while the catalog holds items" as a failed scan rather than a mass deletion. Disable with `"safeScan": false` / `SONDER_SAFE_SCAN=0` to let a deliberately emptied library prune normally. |
| Snapshot writes serialized + directory fsync | `library.Store.Save` | Debounced timer and explicit `Flush` could interleave; rename durability now survives a crash on local filesystems. |
| Empty ffprobe result no longer stamped as probed | `probe.Result.StreamCount`, `scanner.probePending` | `ffprobe` exits 0 with `{"streams":[]}` for broken files; those items were permanently marked probed and never retried or thumbnailed. |
| Plex-migration dead branch fixed | `cmd/sonder/main.go` | `SetSnapshotPath` was never wired, so API-triggered rescans/enrichment never persisted their results. |

### Security

| Change | Where | Why |
| --- | --- | --- |
| DNS-rebinding guard on the loopback bypass | `httpapi.hostIsLoopback`, `withAuth` | Loopback peers are now trusted only when the `Host` header also names loopback (`127.0.0.1`, `localhost`, `::1`). A page that rebinds `evil.example.com` → `127.0.0.1` no longer inherits localhost access or the pairing token. |
| Constant-time pairing-token comparison | `httpapi.tokenMatches` | Replaced `==` with `crypto/subtle` so the token cannot be recovered by timing. |
| Request bodies are rejected, not truncated | `httpapi.jsonDecode` | `http.MaxBytesReader` (1 MiB) plus a trailing-data check, replacing silent `io.LimitReader` truncation. |
| Empty-library-table guard | `httpapi.handleSettingsPut` | `{"libraries":[]}` used to wipe the catalog silently; it now requires `?confirm=empty-libraries`. |

### Concurrency & correctness

| Change | Where | Why |
| --- | --- | --- |
| Config is copy-on-write | `httpapi.Server.cfgPtr` / `updateConfig` | Fixes the proven race where `PUT /api/settings` wrote `*config.Config` fields while handlers read them (including `persistConfig` marshaling a torn config to disk). New `TestConcurrentSettingsWritesAndReads` runs under `-race`. |
| Nil guards on post-mutation re-`Get` | `httpapi` playback handlers | A concurrent scan pruning an item between `SetProgress` and the re-`Get` caused a nil-pointer panic. |
| Idle ffmpeg sessions are reaped | `transcode.Session` | A disconnected client could leave ffmpeg running to the end of the file. Sessions now stop after `SessionIdleTTL` (30 s) with zero readers, preserving warm-seek reuse but bounding orphan processes. Also: the distributor skips the 64 KB copy when no readers are attached, and `spawn` aborts if the request context ends while waiting for a concurrency slot. |
| Deep-copied cloned pointer fields | `library.cloneMediaItem` | `*string`/`*int` fields were aliased into store-owned state, so any caller write would race outside the lock. |
| Empty-probe and ebook-video classification fixes | `scanner.inferKind` | Stray `.webm`/`.m4v`/`.ts`/`.mpg`/`.mpeg`/`.m2ts` inside an ebook library no longer masquerade as books. |
| Parser quality regex repaired | `parser.reQualityParen` | `[^)]*\]` could never match a parenthesised group; corrected to `[^)]*\)`. |
| Artwork content types | `httpapi.serveArtwork` | `.webp`/`.gif`/`.avif`/`.heic` were all served as `image/jpeg`. |

### Performance

| Change | Where | Why |
| --- | --- | --- |
| `Store.CountByLibrary`, `Store.InternalItemsOfKind` | `library.Store` | `GET /api/settings` deep-cloned and sorted all ~23k items just to count per library; `GET /api/audiobooks`/`/api/ebooks` cloned the whole catalog then filtered. Both now touch only the needed items. |
| Snapshot uses `json.Marshal` | `library.Store.Save` | `MarshalIndent` added 15–25% CPU/bytes for no benefit on a periodic write. |
| `statusWriter` forwards `ReadFrom`/`Flush` | `httpapi.statusWriter` | Embedding the `ResponseWriter` interface hid `io.ReaderFrom`, silently disabling `sendfile` for direct-play `/stream` responses. |

### Maintainability & hygiene

- Removed dead code: `serveHTML`, `gunzipOnce`, `derefStr` (×1 of 3), duplicate
  doubled comments.
- De-duplicated the library-kind allowlist into `config.ValidKind`.
- Replaced the duplicated anonymous ffprobe stream struct with a named
  `ffprobeStream` type; added a container-bitrate fallback.
- Replaced `atomic` counters for the enrichment pass (removes a debug-path

- `web/library.html`: replaced **5 literal NUL bytes** embedded in JS string

- `README.md` rewritten: it described the macOS app as the server and never

- CI: added a `gofmt -l` gate and a version stamp
  (`-X main.version=$GITHUB_SHA`) so artifacts no longer report the hardcoded
  `0.1.0`.

## Second pass — P1 implementation

Following the first pass, the next tier of the roadmap was implemented and
verified. All 11 packages pass `go test -race`, `gofmt`/`go vet` are clean, and
a live end-to-end smoke test exercised each behavior.

| Change | Where | Why |
| --- | --- | --- |
| Progress persistence split from the catalog | `library.Store.SaveProgress`/`LoadProgress`/`SaveProgressDebounced`, new `progress.json` sidecar; `httpapi.SetProgressSave` | Every playback heartbeat used to trigger a full ~20 MB catalog marshal + NAS write. Progress now goes to a small sidecar (smoke test: 181 B vs 1.1 KB catalog at 1 item; ~KB vs ~20 MB at 20k) and is overlaid on load. |
| `Store.Update` atomic read-modify-write | `library.Store`, used by the probe pool, thumbnail pool, `RefreshTracks`, and `applyEnrichment` | Eliminates lost updates: a probe or thumbnail write could previously revert a concurrent progress write (and vice versa). Regression test drives 200 concurrent `Update`/`SetProgress` pairs. |
| Bounded, copy-returning caches | `probe.Cache`, `probe.ChapterSource` | Caches grew without limit on a long-lived server and returned shared mutable pointers. FIFO eviction (4096 / 512) and deep-copied results; dead `RunPool` API removed. |
| Transcode audio-track selection | `transcode.Request.AudioTrackN`, `?audio=N` | `/stream?transcode=1` always mapped the first audio track. Clients can now pass the numeric suffix of their selected `embedded-audio:N`; sessions are keyed by audio choice. Documented in `API.md`. |
| Panic recovery | `httpapi.withRecovery` | A handler panic dropped the connection; it now returns 500 and logs the stack. |
| `Vary` + `gzip;q=0` + weak/list ETag | `httpapi.acceptsGzip`, `etagMatches`, `withGzip` | `gzip;q=0` was still compressed; no `Vary: Accept-Encoding` anywhere; `If-None-Match` was a raw string compare that ignored `W/` and lists. |
| Swift migration fidelity | `library.import_swift` | `author`/`narrator` were silently dropped and poster/backdrop URLs were not derived. |

The headline P1 item — **decoupling progress writes from the `/api/library`
payload cache and ETag** — is only partially addressed: persistence is now
cheap, but the in-memory payload is still rebuilt whenever the generation
changes. Completing that needs either a separate `/api/progress` sync route or
a client change, so it remains at the top of the P1 list below.

## Third pass — cancellation, import correctness, response path

| Change | Where | Why |
| --- | --- | --- |
| Scan/probe cancellation + shutdown join | `library.Scanner.ctx`/`Shutdown`, `probePending(ctx)`, walk context check; `main.go` waits on `scanDone` before the final flush | `SIGTERM` used to orphan in-flight `ffprobe`/`ffmpeg` children and could persist a half-applied scan. `Scanner.Shutdown` cancels the context; the walk, probe pool, thumbs pool, and feed loop all observe it. Test: `TestShutdownCancelsInFlightScan`. |
| Per-request cancellation for track/chapter probes | `TrackRefresher.RefreshTracks(ctx, id)`, `ChapterProvider.ChaptersFor(ctx, id)`, `ChapterSource`, `handlers` | A client disconnect now cancels the underlying ffprobe instead of letting it run to completion. |
| Plex-import path canonicalization | `library.CanonicalMediaPath`, `plexItem` | Imported IDs used raw Plex paths while the scanner uses symlink-resolved absolute paths, so imported items were pruned on the next scan. Both now canonicalize; regression test `TestPlexImportIDMatchesScannerID` builds a real Plex DB and asserts ID equality. |
| Comma-safe Plex part parsing | `import_plex.go` (`group_concat(p.file, char(31))`, `plexFirstFile`) | Paths containing commas were silently dropped. Note: SQLite rejects a separator together with `DISTINCT` ("DISTINCT aggregates must have exactly one argument"), so the `DISTINCT` was dropped — duplicates are harmless for first-existing selection. |
| Plex import timeout + wider agent map | `runSQLRows(ctx, …)`, `plexImportTimeout`, `plexGUID` | A locked/corrupt Plex DB could hang startup forever; the whole migration is now bounded at 3 minutes. `tvdb` guids are preserved. |
| `suggestedMounts` cached | `httpapi.suggestedMounts` | Enumerating `/Volumes` + `/mnt` on every settings request could block for seconds on a stale network mount; now cached for 30s. |
| ETag/304 on embedded pages | `webui.gzippedPage`, `serveGzippableHTML`, `handleSharedJS` | HTML and `shared.js` were re-downloaded on every navigation; they now carry a content-hash ETag and honour `If-None-Match`. |
| Configurable thumbnail workers | `config.ThumbWorkers`, `SONDER_THUMB_WORKERS`, `Scanner.SetThumbWorkers` | The thumbnail pool size was hardcoded and had no setter. |
| Shared media-catalog handler | `httpapi.mediaCatalog`, `catalogMatches`; DTOs renamed `catalogItem`/`catalogResponse`/`catalogDetail` | The audiobook and ebook handlers were near-identical copies; author/narrator now participate in search. |

## Fifth pass — built-in player (audiobooks and video)

**Reported:** an `.m4b` audiobook showed “**.M4B** can't play inline. Open in a
native player.” despite `.m4b` being an ordinary MP4/AAC container that
browsers play fine.

**Root cause:** the web UI gated inline playback on a video-only allowlist
(`["mp4","m4v","mov","webm"]`), so every audio format was rejected, and the
media element lived *inside* the detail modal — closing the modal stopped
playback, so there was no background listening.

**Changes**

- `playbackPlan(item)` is the single playability decision: audio containers
  (`m4b`, `mp3`, `m4a`, `aac`, `flac`, `wav`, `ogg`) and browser-safe video
  stream directly; other video kinds (mkv, avi, …) fall back to the server's
  existing on-the-fly fMP4 transcode (`/stream/{id}?transcode=1`); ebooks are
  not streamable. Unit-tested in `library.test.cjs`.
- A **persistent bottom controller** (`#nowPlaying`) sits outside every
  re-rendered region, so audio/video keeps playing across tabs, search, paging,
  edition switching, and closing the detail modal. The detail modal now shows
  metadata plus a Play/Resume/Pause button instead of embedding a player.
- Controls: play/pause, ±30s, a scrubbable seek bar with elapsed/total time,
  playback speed (0.75×–2×), artwork, title/kind/author, and a video
  collapse (“hide video, keep playing”) toggle. Keyboard: space, ←/→ when not
  typing.
- **Background playback:** the Media Session API publishes metadata and
  position and handles play/pause/seek/stop from OS and lock-screen controls;
  progress is written every 15 s, on pause/ended, and on `visibilitychange` /
  `pagehide` (with `keepalive`), so position survives backgrounding and unload.
- Video is a `<video>` in the player; for audio the video surface collapses so
  the element is never `display:none` (which some browsers deprioritise).

**Verification (browser, real fixture):** generated a 180 s AAC `.m4b`; the
server serves it as `audio/mp4` with `206` byte ranges. In ego-browser: the
audiobook played inline (`paused:false`, position advancing), the bar rendered
title/author with `MediaMetadata` and `playbackState:"playing"`, closing the
modal and switching tabs left it playing, +30 s and 1.5× applied, pause
reported `"paused"`, and the position persisted server-side (33.7 s).

## Architecture assessment

### What is healthy

- **Package boundaries are clean and acyclic.** `library` owns catalog + scan +
  parse + persistence; `probe`, `transcode`, and `artwork` are leaf adapters
  behind narrow interfaces (`Prober`, `ThumbFunc`). Probe/transcode/artwork do
  not import each other.
- **The wire contract is explicit and tested.** `API.md` is the source of
  truth, `internal/api/types.go` holds the DTOs, and `golden_test.go` pins the
  shapes.
- **The scan pipeline is thoughtful.** Stable IDs, incremental size+mtime
  skipping, per-scan directory-listing memoization, separate probe and
  thumbnail pools, orphaned-thumbnail reattachment, and parser-version stamps
  that force controlled rebuilds.
- **Transcoding is real.** Remux-first, VideoToolbox/VAAPI/QSV encode paths,
  bounded concurrency, process-group kill, warm-session seek reuse, subtitle
  burn-in.
- **Tests are broad** on the core; `-race` is wired into `make test` and CI.

### What is structurally wrong

1. **Dual server implementations (highest priority).** `SonderHTTPServer.swift`
   (+ `SonderHTTPResponses`/`SonderHTTPTypes`) and `server/internal/httpapi`
   both implement the same routes. The Swift app also keeps its own
   `SonderMediaKind`, `SonderMediaFormat`, `SonderPlaybackTrack`, progress,
   settings, directory, and activity types, hand-mirrored in three places
   (macOS app, `SonderAPI`, Go). Drift is already real:
   - Go emits `author`/`narrator`; `SonderPublicMediaItem` has no such fields,
     so iOS silently drops them. The golden test misses it because
     `omitempty` hides nil.
   - `GET /api/health` and `GET /api/status` return different shapes between
     the two servers; `discoveryMethods` strings differ.
   - Snapshots are one-way: Go imports the Swift `library.json`, but Swift
     cannot read Go's, and Go drops Swift-only state (collections, conversion
     jobs, library definitions, bookmarks).
2. **No shared schema across languages.** `SonderAPI` is Swift-only, so the Go
   DTOs are maintained by hand. A single schema (e.g. generated from one
   source) would eliminate a whole class of drift.
3. **`httpapi` has no service layer.** Handlers reach directly into the store,
   scanner, and transcoder, and `RunEnrichmentPass` (enrichment + Plex art
   install + store mutation + debug tracing) lives in the HTTP package and is
   imported by `main`.
4. **`library.Scanner` is a god-object** (discovery + parse + artwork + two
   worker pools + activity logging). `buildItem` (~123 lines) and
   `scanLibraryInto` (~107) are the natural extraction seams.
5. **A domain package depends on the config layer**: `library` imports
   `config` only for `config.Library`. A `library.Library` value type would
   remove the inversion.

## Prioritized roadmap

### P0 — data integrity, security, and "can a fresh clone even build?"

1. **Fix the iOS gitlink.** `IOS_Client_Xcode/TM_Sonder_Client` is committed
   as mode-160000 with **no `.gitmodules`**, so a fresh clone cannot obtain the

## Plex-replacement gap analysis

**Implemented:** robust filename parser with `{imdb}`/`{tmdb}`/`{audible}`
tags and editions; stable IDs; incremental scanning; ffprobe track probing and
chapters; on-the-fly transcode with hardware encode; direct-play Range/206;
ETag/304 + gzip; embedded + sidecar subtitles; multi-source artwork with
ffmpeg thumbnail fallback; Plex-standard folder meta-libraries; Plex-style web
UI; settings API with directory browser; Bonjour; pairing-token auth;
audiobook chapters/API; ebook catalog; iOS offline downloads and progress
queue.

**Missing for parity, roughly in priority order:**

| Gap | Notes |
| --- | --- |
| Collections & playlists | Exist only in the Swift app; the Go snapshot **drops** them. Highest-value missing "media server" feature. |
| Multi-user accounts & per-user progress | Single shared token, one global progress map. |
| Remote access / HTTPS | No TLS/ACME; Tailscale hint only. |
| Richer metadata agents | Keyless Wikipedia/OpenLibrary/Audnexus only; no TMDB/TVDB by-ID, no TV episode metadata, no trailers. |
| HLS/DASH + adaptive quality | fMP4 progressive + direct only; no bitrate ladder, no trickplay previews. |
| Music library | No artist/album/track concepts. |
| Live TV / DVR | None. |
| DLNA/UPnP | Bonjour only. |
| Client breadth | No tvOS/Android; iOS EPUB reader unimplemented (PDF works). |
| Skip intro/credits, watchlist, ratings, sharing | None. |
| Subtitle download/upload | Sidecar + embedded playback only. |
| Federation | `feature_federation.md` is design-only. |

Metadata debt is also real: ebooks ~51% covered, audiobooks ~82%, and authors
unpopulated across ~923 audiobook items.

## Repo, release & ops hygiene

- **`.git/objects` is ~312 MB for a 143-file repo** — ~305 MB of dangling loose
  blobs (Matroska media committed then rewritten out). `git gc --prune=now`
  reclaims it.
- **Tracked build artifacts:** `tools/sonder-menu/sonder-menu` (Mach-O) and two
  large PNGs under `DesignAssets/`. The `bin/` binaries are correctly ignored.
- **Inverted ignore policy:** curated `report.txt`/`status.txt` are ignored
  while raw planning HTML (`roadmap.html`, `ios-roadmap.html`,
  `requirements_Client.html`) and `opencode.json` are tracked.
- **No LICENSE, CHANGELOG, or git tags.** Go reports `0.1.0`; Swift
  `MARKETING_VERSION = 1.0`; `make` stamps a date. Versioning should be unified
  (CI now stamps Go artifacts from the commit SHA).
- **`xcode-TM-SonderUITests/` is empty.**
- **`deploy/Containerfile` copies `server/go.sum*`, but there is no `go.sum`**
  (the server has zero third-party dependencies) — harmless today, misleading
  tomorrow.
- CI covers the Go server, SonderAPI, and macOS tests, but **not** the iOS app —
  blocked on the gitlink issue above.

## Appendix — audit evidence highlights

- **Proven config race (fixed):** `handleSettingsPut` writes vs
  `requiresPairing`/`handleHealth` reads, reproduced under `-race` with a Go
  overlay test; also `persistConfig` marshaled concurrently-written config.
- **Proven dead persistence branch (fixed):** every `s.snapshotPath != ""`
  guard in `settings.go` was false because `SetSnapshotPath` had no caller.
- **Proven regression caught mid-audit (fixed properly):** the first iteration
  of the scan-safety net made deleting the last item of any library
  impossible; `TestRemovalDetection` failed. The final design keeps genuine
  removals working (multi-item library test), preserves unreadable libraries
  unconditionally, and gates the empty-scan heuristic behind `safeScan` with
  dedicated on/off tests.
- **`/api/library` cost:** ~16.3 MB payload, ~150 ms cold, cached per
  generation; a progress ping changes the generation and therefore the ETag.
- **Weak existing test (noted):** `TestClientDisconnectKillsFfmpegFast` passed
  only because its 6-second fixture finishes in ~0.35 s; the new deterministic
  idle-reap tests exercise the lifecycle without relying on ffmpeg timing.
